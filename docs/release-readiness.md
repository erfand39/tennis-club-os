# گزارش پذیرش و آمادگی انتشار محلی باشگاه تنیس سام

## وضعیت

نسخهٔ تحویل برای پذیرش روی مک آماده است. اجرای برنامه و بازیابی در محیط جدا با PostgreSQL 17.11، Supabase Auth 2.189.0 و ساخت تولیدی Next.js 16.4.6 انجام شد. همهٔ عملیات با حساب‌ها و رکوردهای آزمایشی اجرا شدند.

## نتیجهٔ آزمون

نتیجهٔ نسخهٔ جاری در [GitHub Actions](https://github.com/erfand39/tennis-club-os/actions/workflows/ci.yml) ثبت می‌شود. گردش عادی بررسی TypeScript، lint، ساخت تولیدی، آزمون‌های HTTP، دیتابیس و PWA را اجرا می‌کند. آزمون بازیابی در اجرای دستی گردش‌کار فعال است.

- در یک گردش متصل، زمین، ساعات، تعرفه، مربی و شاگرد با API مدیر ثبت شدند. یک کلاس گروهی رزرو و دو نفر ثبت‌نام شدند. پس از جلو بردن زمان سناریو در دادهٔ آزمایشی، حضور، فاکتور، دریافت تکرارشده با همان شناسه، بازپرداخت و تسویه با API ثبت شدند. تعداد دریافت یک بود. مبلغ خالص ۹۰۰٬۰۰۰ ریال، مانده ۳۰۰٬۰۰۰ ریال و تسویهٔ مربی ۴۰۰٬۰۰۰ ریال با دیتابیس تطبیق داشت. چهار سطح گزارش و خروجی Excel برای همان گردش بررسی شدند.
- آزمون‌های مجزا فعال‌سازی و بایگانی پرونده، تعمیرات، رزرو خصوصی، لغو، جابه‌جایی ناموفق، رقابت زمین و مربی و شاگرد، ظرفیت کلاس، بستهٔ آموزشی، محدودیت دسترسی شعبه، وضعیت نشست و تاریخچهٔ تغییرات را پوشش می‌دهند. دسترسی HTTP به مسیرهای فایل تنظیمات، آرشیو و SQL بسته بود و درخواست فایل با قالب پشتیبانی‌نشده رد شد. ممیزی وابستگی‌های تولیدی npm و بررسی هشدارهای دیتابیس موردی گزارش نکردند.
- یک آرشیو واقعی `pg_dump` در پایگاه دادهٔ جدا با `pg_restore` بازیابی شد. محتوای ۲۲ جدول، شامل حساب‌ها، رزرو، حضور، دریافت، بازپرداخت، ثبت عملیات و تاریخچهٔ مهاجرت، با شمارش و اثرانگشت ردیف‌ها تطبیق داشت. نسخهٔ بازیابی‌شده با سرویس ورود و برنامهٔ تولیدی بالا آمد. ورود مالک با همان گذرواژه و بازکردن فاکتور بازیابی‌شده موفق بود. آرشیو ناقص رد شد و دادهٔ منبع آزمایشی بدون تغییر ماند.
- در دیتابیس بازیابی‌شده، خطای عمدی در مهاجرت، ساخت جدول و ثبت مهاجرت را برگرداند. اجرای دوبارهٔ مهاجرت موفق تغییری ایجاد نکرد. فایل دستکاری‌شده و اجرای نسخهٔ قدیمی روی تاریخچهٔ جدیدتر رد شدند.
- در یک اجرای ثبت‌شده، هشت درخواست هم‌زمان گزارش روی loopback در ۳۰۷ تا ۴۲۹ میلی‌ثانیه پاسخ گرفتند. آزمون تقویم با ۲۴۰۰ ردیف تاریخی استفاده از ایندکس محدوده و زمان اجرای حدود ۱٫۹ میلی‌ثانیه را ثبت کرد. این اعداد مربوط به دادهٔ آزمایشی و محیط اندازه‌گیری هستند.

## یافته‌ها و اصلاحات

| اهمیت | یافته | اصلاح و بازآزمایی |
| --- | --- | --- |
| زیاد | بازیابی قبلاً به آماده‌سازی دستی نقش‌ها و دیتابیس نیاز داشت. | دستورهای بررسی آرشیو و آماده‌سازی حجم بازیابی اضافه شدند. آرشیو سالم، فایل ناقص، تطبیق ردیف‌ها و ورود مالک پس از بازیابی آزموده شدند. |
| زیاد | تطبیق نسخه قبل از اعمال کل فهرست مهاجرت‌ها انجام نمی‌شد. | بررسی کل تاریخچه، checksum و ترتیب هر مجموعه پیش از اعمال تغییر اضافه شد. حالت بازگشت ناقص، تاریخچهٔ جدیدتر و اجرای مجدد آزموده شدند. |
| متوسط | خطای غیرمنتظرهٔ API شناسهٔ قابل‌تطبیق در پاسخ و لاگ نداشت. | شناسهٔ `X-Sam-Trace` به پاسخ و رخداد محلی اضافه شد. پاسخ خطا همچنان کد عمومی می‌دهد. |

## پذیرش روی دستگاه واقعی

| مورد باز | آزمون موردنیاز |
| --- | --- |
| Docker Desktop روی مک مقصد | نصب یا به‌روزرسانی، بررسی پشتیبان در Docker و بالا آمدن بعد از ورود دوباره به macOS |
| آیفون و Push واقعی | اتصال HTTPS در شبکهٔ باشگاه، نصب از Safari، دریافت اعلان و ورود به رکورد پس از لمس اعلان |
| عملکرد روی شبکه و دستگاه مقصد | اندازه‌گیری LCP، INP و CLS با داده و دستگاه مورد استفادهٔ باشگاه |

## راهنمای تحویل

از [راهنمای نصب محلی](local-run.md)، [پشتیبان و بازیابی](recovery.md) و [نصب آیفون و اعلان‌ها](pwa.md) استفاده کنید. کلیدهای برنامه در فایل تنظیمات همان نصب نگهداری می‌شوند. PostgreSQL و سرویس ورود از شبکهٔ داخلی Docker استفاده می‌کنند. برای به‌روزرسانی ابتدا پشتیبان بررسی‌شده تهیه کنید و سپس `./scripts/local.sh up` را اجرا کنید.

برای بازتولید آزمون بازیابی، ابتدا `test:local` را روی نصب خالی آزمایشی اجرا کنید. سپس `SAM_RECOVERY_SOURCE_URL` را به همان PostgreSQL آزمایشی روی loopback بدهید و با ابزارهای PostgreSQL 17 در PATH، `npm run test:recovery` را اجرا کنید. برای بخش ورود واقعی، مسیر اجرای GoTrue و مهاجرت‌های آن را به‌ترتیب در `SAM_RECOVERY_AUTH_BIN` و `SAM_RECOVERY_AUTH_MIGRATIONS` قرار دهید و همان گذرواژهٔ آزمایشی `SAM_TEST_OWNER_PASSWORD` را به هر دو آزمون بدهید.
