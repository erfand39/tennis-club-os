# نصب محلی باشگاه تنیس سام

## راه‌اندازی روی مک

Docker Desktop را برای پردازندهٔ مک خود نصب و باز کنید. سورس مخزن خصوصی را با حساب GitHub خود دریافت کنید. از پوشهٔ پروژه در Terminal این دستورها را اجرا کنید.

```sh
./scripts/local.sh up
./scripts/local.sh setup-code
```

آدرس `http://127.0.0.1:3030` را باز کنید و کد نصب، ایمیل، نام و گذرواژهٔ مالک را وارد کنید. این فرم یک‌بار برای ساخت مجموعه و شعبهٔ مرکزی نمایش داده می‌شود. راه‌اندازی اول برای دریافت تصویرهای Docker و وابستگی‌ها به اینترنت نیاز دارد. اگر پورت ۳۰۳۰ اشغال است، در **اولین راه‌اندازی** به‌جای دستور اول از `SAM_LOCAL_PORT=3031 ./scripts/local.sh up` استفاده کنید.

## استفادهٔ روزمره

| دستور | نتیجه |
| --- | --- |
| `./scripts/local.sh start` | راه‌اندازی با تصویرهای نصب‌شده. پس از نصب اولیه، بدون دانلود اجرا می‌شود. |
| `./scripts/local.sh stop` | توقف سرویس‌ها با حفظ دادهٔ محلی |
| `./scripts/local.sh up` | ساخت نسخهٔ جدید و اعمال مهاجرت‌های جدید پس از به‌روزرسانی سورس |
| `./scripts/local.sh status` | وضعیت برنامه، Auth، PostgreSQL و اجرای مهاجرت |
| `./scripts/local.sh logs` | آخرین پیام‌های سرویس‌ها |
| `./scripts/local.sh backup` | تولید فایل `.dump` محلی در `.local/backups/` |
| `./scripts/local.sh recover OWNER_EMAIL` | تولید پیوند بازیابی یک‌بارمصرف برای مالک |

سرویس‌ها با سیاست `unless-stopped` اجرا می‌شوند. برای بالا آمدن بعد از ورود به macOS، در تنظیمات Docker Desktop گزینهٔ **Start Docker Desktop when you sign in to your computer** را فعال کنید. اگر سرویس‌ها را با دستور `stop` متوقف کرده‌اید، برای اجرای دوباره از `start` استفاده کنید. [تنظیمات Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/)

## ماندگاری و پشتیبان

PostgreSQL از حجم نام‌دار `sam-tennis-pgdata-v1` استفاده می‌کند. به‌روزرسانی سورس، ساخت مجدد تصویر یا توقف برنامه، این حجم را حذف نمی‌کند. تنظیمات و کلیدهای نصب در `.local/secrets.env` روی سیستم می‌مانند. هنگام جابه‌جایی پوشهٔ پروژه، فایل تنظیمات همان نصب را همراه سورس منتقل کنید. برای انتقال یا بازیابی، فایل پشتیبان دیتابیس و یک نسخهٔ محافظت‌شده از فایل کلیدها را با هم نگه دارید. پاک‌سازی حجم‌های Docker یا بازنشانی کامل Docker Desktop می‌تواند دادهٔ روی حجم را پاک کند. [حجم‌های Docker](https://docs.docker.com/engine/storage/volumes/)

فایل `.dump` شامل طرح و دادهٔ برنامه، Auth و تاریخچهٔ مهاجرت است. برای سنجش بازیابی، روی یک PostgreSQL ۱۷ جدا، نقش‌های `supabase_auth_admin`، `tennis_web`، `anon` و `authenticated` را مطابق فایل راه‌اندازی بسازید و آرشیو را با `pg_restore --exit-on-error --single-transaction` در دیتابیس خالی بازیابی کنید. سپس نام مجموعه، کاربران و تاریخچهٔ مهاجرت‌ها را بررسی کنید. در یک نصب بازیابی‌شده، فایل کلیدهای همان نصب برای اتصال سرویس‌ها و بازکردن نشست‌ها لازم است. آزمون بازیابی کامل روی Docker Desktop مک در همین فاز اجرا نشده است.

## معماری اجرا و دسترسی

- برنامهٔ Next.js روی آدرس loopback منتشر می‌شود. PostgreSQL و Supabase Auth روی شبکهٔ داخلی کانتینرها هستند. اجرای نسخهٔ محلی به حساب Supabase Cloud وابسته نیست.
- در هر راه‌اندازی، مهاجرت‌های SQL با ترتیب نسخه، قفل هم‌زمانی و کنترل checksum اجرا می‌شوند. سرویس مهاجرت با اختیار دیتابیس مجزا است. برنامهٔ روزمره از کاربر محدود `tennis_web` استفاده می‌کند.
- مرورگر فقط شناسهٔ تصادفی نشست را در کوکی HttpOnly دریافت می‌کند. هش شناسه و توکن‌های رمزگذاری‌شده در PostgreSQL نگهداری می‌شوند. عملیات باشگاه در تراکنشی با نقش `authenticated` و شناسهٔ بررسی‌شدهٔ کاربر اجرا می‌شود.
- حساب مالک از طریق کد نصب ساخته می‌شود. دعوت و بازیابی با پیوند یک‌بارمصرف انجام می‌شوند. پیوند روی همین سیستم باز می‌شود. مالک دسترسی شعبه، وضعیت و نقش کاربران را از پنل مدیریت می‌کند.
- نمونهٔ Sites از دادهٔ ساختگی استفاده می‌کند و ورود نمونه با انتخاب نقش انجام می‌شود. نسخهٔ محلی، نقش‌ها و نشست‌ها را در سرور و دیتابیس اعمال می‌کند.

## اعتبارسنجی فاز ۰۳

ساخت تولیدی Next.js، بررسی TypeScript و پیکربندی Compose انجام شد. آزمون‌های HTTP روی Next.js، PostgreSQL ۱۷٫۱۱ و باینری رسمی Supabase Auth نسخهٔ ۲٫۱۸۹٫۰ اجرا شدند. هفت آزمون HTTP، دوازده آزمون دیتابیس و هفت آزمون نمونه موفق بودند. پس از راه‌اندازی مجدد PostgreSQL، نصب همچنان تنظیم‌شده بود و صفحهٔ ورود به حساب موجود نمایش داده شد. نمونهٔ ورود و نقش‌ها در مرورگر دسکتاپ و عرض‌های ۳۲۰ و ۳۹۰ پیکسل بررسی شد.

اجرای سرتاسری خود Docker Desktop روی مک باید هنگام نصب روی دستگاه بررسی شود. در این فاز راه‌اندازی، هویت، دسترسی، پروفایل و نمای کلی محلی فعال‌اند. فرم‌های مدیریت زمین، مربی و شاگرد و اتصال تقویم عملیاتی مطابق فازهای بعدی اضافه می‌شوند.
